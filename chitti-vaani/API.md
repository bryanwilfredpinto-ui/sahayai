# API — Chitti Vaani

All endpoints are Flask Blueprints registered in [main.py](backend/main.py). The base service runs on port `8003` locally and at `https://chitti-vaani-api.up.railway.app` in production.

## App-level

### `GET /`
Service banner.

**Response**
```json
{"app": "Chitti Vaani API", "version": "1.0.0", "status": "ok"}
```

### `GET /health`
Liveness.

**Response**
```json
{"ok": true}
```

## `/api/vaani/*` — Conversational layer ([vaani.py](backend/routes/vaani.py))

### `POST /api/vaani/ask`
DeepSeek-backed reply. Frontend MUST read `reply` aloud (it already contains the legal disclaimer).

**Request body**
| Field | Type | Required | Notes |
|---|---|---|---|
| `text` | string | yes | max 6000 chars |
| `language` | string | no | default `hi`. Known: `hi`, `en`, `ta`, `te`, `bn`, `mr`, `gu`, `kn`, `ml`. Unknown codes fall through. |
| `mode` | string | no | one of `ask` (default), `call` (summarise call notes), `read` (read back verbatim), `translate` |

**Response**
```json
{
  "ok": true,
  "source": "deepseek",          // or "fallback" if DEEPSEEK_API_KEY missing
  "language": "hi",
  "reply": "<text — frontend MUST speak this aloud>",
  "model": "deepseek-chat",
  "tokens": {"input": 123, "output": 45}
}
```

Errors: `400 bad_request` if `text` empty, `413 payload_too_large` if `text > 6000`.

### `GET /api/vaani/health`
DeepSeek configuration diagnostic.

**Response**
```json
{"ok": true, "service": "vaani", "deepseek_configured": true, "model": "deepseek-chat"}
```

### `GET /api/vaani/languages`
List of UI-grade names for the frontend selector.

**Response**
```json
{ "items": [ {"code": "hi", "name": "हिन्दी (Hindi)"}, ... ] }
```

## `/api/vaani/email/*` — Gmail OAuth + send-as-user ([email.py](backend/routes/email.py))

Per-end-user. `user_token` is generated by the frontend on first run (UUID), stored in `localStorage`, sent with every request.

### `GET /api/vaani/email/status?user_token=<uuid>`
**Response**
```json
{
  "ok": true,
  "configured": true,                    // GOOGLE_CLIENT_ID + SECRET set?
  "redirect_uri": "https://.../email/auth/callback",
  "scopes": ["...gmail.send", "...userinfo.email"],
  "connected": true,                     // present only if user_token sent
  "email": "alice@gmail.com",
  "expires_in": 3245
}
```

### `POST /api/vaani/email/auth/start`
Returns the Google consent URL.
**Request**: `{ "user_token": "...", "redirect": "https://sahayai.in/chitti_vaani.html" }`
**Response**: `{ "ok": true, "url": "https://accounts.google.com/o/oauth2/v2/auth?..." }` or `{ ok: false, error }` if OAuth not configured.

### `GET /api/vaani/email/auth/callback?code=&state=&error=`
**Public** (Google can't carry headers). On success, redirects back to the frontend with `?email_connected=1&email=<addr>`, or renders an inline success page if no `redirect` was passed. Error path renders an inline failure page.

### `POST /api/vaani/email/send`
**Request body**
| Field | Type | Required | Notes |
|---|---|---|---|
| `user_token` | string | yes | min 8 chars |
| `to` | string | yes | recipient email |
| `subject` | string | no | default `(no subject)` |
| `body` | string | yes | max 20 000 chars; Chitti AI signature auto-appended |
| `user_real_name` | string | no | included in the signature |

**Response**
```json
{
  "ok": true,
  "message_id": "1830abc...",
  "thread_id": "1830abc...",
  "from": "alice@gmail.com",
  "to": "bob@example.com",
  "subject": "Hello",
  "speak_hi": "Email bhej diya.",
  "speak_en": "Email sent."
}
```

Errors: `400` (missing field / invalid `to`), `413` (body > 20 000), `400` with `{ok:false, error:"no_connected_account"}` if not connected.

### `POST /api/vaani/email/disconnect`
Revokes refresh token (best-effort) and deletes local row.
**Request**: `{ "user_token": "..." }`
**Response**: `{ "ok": true, "removed": true }`

## `/api/vaani/emergency/*` — 24/7 cascade ([emergency.py](backend/routes/emergency.py))

All bodies require `user_token` (≥ 8 chars).

### `POST /api/vaani/emergency/trigger`
Frontend or Android EmergencyMonitor fires this on keyword detection.
**Request**
```json
{
  "user_token": "...",
  "reason": "keyword spotted: bachao",
  "transcript": "...up to 1000 chars...",
  "source": "web"   // or "android"
}
```
**Response**
```json
{
  "ok": true,
  "partners_notified": 2,
  "fanout_ids": [42, 43],
  "reminder_to_frontend": "Frontend MUST run the local cascade: master-confirm 10s, then alarm via STREAM_ALARM, then outbound call to spouse. NEVER auto-dial cops."
}
```

### `POST /api/vaani/emergency/check-in`
Master responded "theek hun" — abort cascade and notify pairs.
**Request**: `{ "user_token": "...", "said": "theek hun" }`
**Response**: `{ "ok": true, "partners_notified": 2 }`

### `POST /api/vaani/emergency/pair/issue`
Issue a 6-digit pair code valid 5 minutes.
**Request**: `{ "user_token": "...", "label": "Mom's phone" }`
**Response**: `{ "ok": true, "code": "473812", "expires_in_seconds": 300 }`

### `POST /api/vaani/emergency/pair/accept`

**Request**: `{ "user_token": "...", "code": "473812", "label": "Anil (son)" }`
**Response (success)**: `{ "ok": true, "pair": {"user_a": "...", "user_b": "...", "label_for_a": "...", "label_for_b": "..."} }`
**Response (fail)**: `{ "ok": false, "error": "code invalid, expired, or self-pair" }`

### `POST /api/vaani/emergency/pair/unpair`
**Request**: `{ "user_token": "...", "partner_token": "..." }`
**Response**: `{ "ok": true, "removed": true }`

### `GET /api/vaani/emergency/pair/list?user_token=<uuid>`
**Response**
```json
{ "ok": true, "partners": [ {"partner_token": "...", "partner_label": "Anil (son)", "since": 1715380000} ] }
```

### `GET|POST /api/vaani/emergency/poll`
Long-poll-equivalent. Returns and marks-delivered any queued events.
**GET**: `?user_token=<uuid>`
**POST body**: `{ "user_token": "..." }`
**Response**
```json

  "ok": true,
  "events": [
    {
      "id": 42,
      "from": "<partner user_token>",
      "kind": "emergency",     // or "emergency_check_in"
```

## `/api/vaani/local/*` — Local-Chitti-first lookup ([local.py](backend/routes/local.py))

The "Order & book" Pro Action cards consult this endpoint before opening any external app (Zomato / Swiggy / Ola / Uber / Rapido / BookMyShow / IRCTC / BigBasket / Blinkit). A registered Chitti shop in the matching service category is always preferred; external links are pure fallback. Directory data is the existing `product_gmail_accounts` table seeded by [`admin_seed.py`](backend/scripts/admin_seed.py).

### `GET /api/vaani/local/nearby?service=<category>[&lat=&lng=&pincode=&radius_km=]`
Look up Chitti shops registered for a service category — **filtered by distance from the user** when a location is supplied — plus the external-app keys that the frontend may use as fallback.

**Query**
- `service` — required. One of: `food`, `restaurant`, `groceries`, `grocery`, `kirana`, `dairy`, `pharmacy`, `medicine`, `medical`, `salon`, `haircut`, `stationery`, `books`, `hardware`, `clothing`, `clothes`, `electronics`, `furniture`, `cab`, `ride`, `auto`, `movies`, `movie`, `tickets`, `train`, `trains`.
- `lat` + `lng` — optional. Decimal degrees. Must be supplied together. When present, the server computes Haversine distance from the user to every shop with `lat`/`lng` and filters by `radius_km`.
- `pincode` — optional. India 6-digit (`^[1-9]\d{5}$`). Used as a fallback when GPS is unavailable, and to pick the default radius (5 km when the pincode prefixes a known metro: `400 / 110 / 560 / 600 / 700 / 500 / 411 / 380 / 201 / 122`; 25 km otherwise). Shops with the same pincode get `distance_km: 0.0` and `geo_match: "pincode_exact"`.
- `radius_km` — optional. Caller override in `(0.1, 200]`. Disables the 5 km → 25 km auto-expansion (see below).

**Response**
```json
{
  "ok": true,
  "service": "food",
  "display": "food delivery",
  "geo_applied": true,
  "radius_km": 5.0,
  "expanded_to_km": null,
  "user_loc": {"lat": 19.0825, "lng": 72.8811, "pincode": "400002"},
  "local": [
    {
      "product_key":       "chittirestaurant_mumbai",
      "product_name":      "Chitti Restaurant Mumbai",
      "gmail_address":     "chittirestaurant.mum@gmail.com",
      "domain_template":   "food_business",
      "features":          ["menu management", "online orders"],
      "oauth_status":      "connected",
      "lat":               19.0760,
      "lng":               72.8777,
      "pincode":           "400001",
      "service_radius_km": null,
      "distance_km":       0.806,
      "geo_match":         "haversine"
    }
  ],
  "local_chitti_keys": ["chittirestaurant"],
  "external_keys":     ["zomato", "swiggy"],
  "note": "Local Chitti business comes first. External apps are a fallback the user can pick if the local Chitti is unreachable."
}
```

Per-row fields added by the geo layer:
- `distance_km` — float, `null` for shops without lat/lng when the user supplied lat/lng (genuinely unknown).
- `geo_match` ∈ `haversine` (Haversine on both pairs) · `pincode_exact` (same 6-digit PIN, `distance_km = 0.0`) · `pincode_different` (known not-local — these are **dropped** from `local`) · `unknown` (one side missing geo — kept in `local` so half-onboarded admins are not hidden, but does NOT count toward "we found something").

Sort order: distance ascending (None last), then connected mailboxes first within the same bucket.

**5 km → 25 km auto-expansion.** When the caller did not supply `radius_km`, the chosen default was 5 km (metro pincode), AND zero shops had `geo_match ∈ {haversine, pincode_exact}` within 5 km, the server retries internally at 25 km and sets `expanded_to_km` on the response. The frontend uses this to render *"No Chitti business within 5 km — expanded search to 25 km."* — never silently widens.

**No location supplied.** When neither `lat/lng` nor `pincode` is sent, the endpoint falls back to the pre-geo "directory-wide" mode: `geo_applied: false`, no `distance_km`, no filtering. The frontend banner explicitly tells the user *"No location set — Chitti is showing the full directory"* with a "Set location" link so silent country-wide results never look like an answer.

Categories with no Chitti shop yet (`cab`, `movies`, `train`, …) return `local: []` and a non-empty `external_keys`. The frontend treats that as a signal to skip the directory block and go straight to the external fallback.

Errors: `400 bad_request` if `service` missing or unknown, if `lat` is set without `lng` (or vice-versa), or if any of `lat / lng / pincode / radius_km` fails range / format validation.

### `GET /api/vaani/local/categories`
Diagnostic. Lists every supported service category, the shop-Chitti product keys it maps to, and the external-app keys.

**Response**
```json
{
  "ok": true,
  "items": [
    {"service": "food", "local_chitti_keys": ["chittirestaurant"], "external_keys": ["zomato", "swiggy"], "display": "food delivery"},
    {"service": "cab",  "local_chitti_keys": [], "external_keys": ["ola", "uber", "rapido"], "display": "cab"},
    ...
  ]
}
```

## `/api/admin/*` — Sahay AI Admin Dashboard ([admin.py](backend/routes/admin.py))

**Auth**: every endpoint except the OAuth callback requires `?secret=<ADMIN_SECRET>` or `X-Admin-Secret: <secret>` header. Missing `ADMIN_SECRET` env var → all admin routes return **503 fail-closed**.

### `GET /api/admin/products`
List products + scheduler status.
**Response**
```json
{
  "ok": true,
  "count": 17,
  "items": [
    {
      "id": 1, "product_key": "chittinews", "product_name": "Chitti News",
      "gmail_address": "chittinews@gmail.com",
      "oauth_status": "connected", "connected_email": "chittinews@gmail.com",
      "domain_template": null, "features": [],
      "token_expires_in": 2895,
      "last_keep_alive_at": "...", "last_keep_alive_ok": true,
      "last_keep_alive_msg": "...", "next_keep_alive_at": "...",
      "created_at": "...", "updated_at": "..."
    }
  ],
  "scheduler": {"running": true, "tz": "Asia/Kolkata", "notify_email": "...", "jobs": [...]},
  "oauth_configured": true,
  "notify_email": "sire@gmail.com",
  "domain_templates": ["shop_management", "healthcare", ...]
}
```

### `POST /api/admin/products`
Add a product row in `oauth_status="needs_auth"`.
**Request**
```json
{
  "product_key": "chittinews",
  "product_name": "Chitti News",
  "gmail_address": "chittinews@gmail.com",
  "domain_template": "shop_management",     // optional, must be a known template
  "features": ["inventory", "billing"]      // list or comma-separated string, ≤ 1024 chars
}
```
**Response**: `201 { "ok": true, "item": {...} }` or `400` / `409` if `product_key` already exists.

Validation:
- `product_key` matches `^[a-z][a-z0-9_]{1,62}$`
- `product_name` 1..128 chars
- `gmail_address` contains `@`, ≤ 256 chars
- `domain_template` ∈ {`shop_management`, `healthcare`, `food_business`, `appointment_management`, `perishable_goods`, `inventory_management`, `b2b_inventory`, `retail_fashion`, `electronics_retail`, `large_item_retail`}

### `DELETE /api/admin/products/<id>`
Best-effort token revoke, then row delete.
**Response**: `{ "ok": true, "deleted_id": 1 }`

### `PATCH /api/admin/products/<id>/geo`
Backfill / update the four geo columns (`lat`, `lng`, `pincode`, `service_radius_km`) on an existing product row. Required so the 17 seeded rows can be given coordinates after the migration — `admin_seed.py` leaves all four columns null.

**Request body** — every field independently optional. To **clear** a field send the empty string for it.
| Field | Type | Notes |
|---|---|---|
| `lat` | float | `[-90, 90]` |
| `lng` | float | `[-180, 180]` |
| `pincode` | string | `^[1-9]\d{5}$` |
| `service_radius_km` | float | `(0, 200]` |

At least one of the four must be supplied or cleared — otherwise `400`.

**Response**: `{ "ok": true, "item": { …full product row… } }`. Action-log entry: `geo_set` with the supplied values.

**Why a separate endpoint instead of `PATCH /products/<id>`:** geo is the only product field admins need to mutate post-OAuth; everything else (key/name/email/domain/features) goes through delete + re-create.

### `POST /api/admin/products/<id>/authorize`
Build the Google consent URL.
**Request**: `{ "redirect": "https://sahayai.in/chitti_admin_products.html" }`
**Response**: `{ "ok": true, "url": "https://accounts.google.com/o/oauth2/v2/auth?..." }` or error if OAuth not configured.

### `GET /api/admin/products/oauth/callback?code=&state=&error=`
**Public** — Google can't carry our `X-Admin-Secret`. Auth is the state token (96-char opaque, single-use, 10 min TTL). On success redirects to `frontend_redirect` (if provided) with `?admin_authorized=1&email=<addr>[&mismatch=1]`, otherwise renders inline result HTML.

### `POST /api/admin/products/<id>/keepalive`
Force a keep-alive send for one product. Returns the upstream Gmail send result.
**Response (ok)**: `{ "ok": true, "message_id": "...", "from": "...", "to": "...", "subject": "..." }`
**Response (skipped)**: `{ "ok": true, "skipped": true, "reason": "already_sent_this_month" }` (only if `force=false` — this endpoint uses `force=true`)
**Response (fail)**: `{ "ok": false, "error": "oauth_needs_auth" | "gmail_http_xxx" | ..., "detail": "..." }`

### `POST /api/admin/products/keepalive-all`
Force a keep-alive run across every product.
**Request**: `{ "force": true | false }`
**Response**
```json
{
  "started_at": "...", "finished_at": "...",
  "ok": 12, "fail": 1, "skipped": 4,
  "results": [ {"product_id": 1, "ok": true, "message_id": "..."}, ... ]
}
```

### `GET /api/admin/products/<id>/logs?limit=20`
Last N rows from `product_action_logs`. `limit` clamped to 1..200, default 20.
**Response**
```json
{
  "ok": true, "count": 5,
  "items": [
    {"id": 88, "action": "keepalive_ok", "status": "ok", "detail": "...", "created_at": "..."},
    ...
  ]
}
```

### `GET /api/admin/scheduler`
Diagnostic.
**Response**: `{ "running": true, "tz": "Asia/Kolkata", "notify_email": "sire@gmail.com", "jobs": [{"id": "monthly_keepalive_all", "next_run": "...", "trigger": "..."}] }`

## `/api/feedback/*` — Cross-product widget ([feedback.py](backend/routes/feedback.py))

`/collect` is **open** (pre-launch, no user accounts). All other endpoints require `ADMIN_SECRET` (same gate as `/api/admin/*`).

### `POST /api/feedback/collect`
Posted by the widget on every Chitti page.
**Rate limit**: 1 req / IP / second, 60 req / IP / hour. Over-limit → `429 {ok:false, error:"rate_limited"}` with no DB write.
**Request body**
| Field | Type | Required | Notes |
|---|---|---|---|
| `page` | string | yes | matches `^[a-z][a-z0-9_]{1,63}$` |
| `type` | string | yes | one of `thumbs_up`, `thumbs_down`, `suggestion` |
| `text` | string | only if `type=suggestion` | ≥ 3 chars, max 2000 |
| `email` | string | no | optional reply-to, max 256 |
| `user_segment` | string | no | one of `blind`, `deaf`, `mute`, `illiterate`, `elderly`, `general` (default `general`) |

**Response**: `201 { "ok": true, "id": 123 }`.

### `GET /api/feedback/report`
Returns the most recently generated daily report (cached in memory). Generates one on the fly if no run has happened yet.
**Response**
```json
{
  "generated_at": "...",
  "lookback_hours": 24,
  "total_feedback_collected_all_time": 412,
  "thumbs_counts_window":  [{"page": "chitti_vaani", "thumbs_up": 22, "thumbs_down": 3}, ...],
  "thumbs_counts_all_time": [...],
  "top_suggestions": [
    {"id": 88, "page": "chitti_vaani", "text": "...", "user_segment": "blind",
     "emails": [...], "frequency": 3, "first_seen": "...", "score": 4.5,
     "score_components": {"impact": 1.0, "frequency": 3, "urgency": 1.5, "effort": 1.0}}
  ],
  "all_suggestions": [...],
  "removed_one_word": 2, "removed_impossible": 1, "removed_duplicate": 4
}
```

### `POST /api/feedback/run-now`
Regenerate the report immediately (also emails it if a connected admin product mailbox exists and `ADMIN_NOTIFY_EMAIL` is set).
**Request**: `{ "lookback_hours": 24 }` (clamped 1..720)
**Response**: same shape as `/report`.

### `GET /api/feedback/list?type=&page=&show_junk=0&limit=100`
Raw rows for the dashboard table.
**Query**
- `type` — optional filter (`thumbs_up` / `thumbs_down` / `suggestion`)
- `page` — optional filter
- `show_junk` — `1` / `true` / `yes` to include junk rows (default hides them)
- `limit` — 1..500, default 100

**Response**
```json
{
  "ok": true, "count": 100,
  "items": [
    {"id": 123, "page": "chitti_vaani", "type": "suggestion", "text": "...",
     "email": "...", "user_segment": "blind", "is_junk": false, "created_at": "..."}
  ]
}
```

### `POST /api/feedback/<id>/junk`
Manually toggle junk flag.
**Request**: `{ "undo": false }` (set `true` to clear)
**Response**: `{ "ok": true, "id": 123, "is_junk": true }`

### `GET /api/feedback/health`
**Response**
```json
{
  "ok": true,
  "scheduler": {"running": true, "tz": "Asia/Kolkata", "last_run_at": "...", "jobs": [...]},
  "total_all_time": 412
```

## Error response shape (all endpoints)

```json
{ "error": "bad_request" | "not_found" | "method_not_allowed" | "payload_too_large" | "internal_server_error",
  "detail": "human-readable description" }
```

Status codes follow standard conventions. Body cap is **1 MB** (`MAX_CONTENT_LENGTH`).
